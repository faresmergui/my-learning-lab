- q: Quelles sont les principales classes de stockage S3 ?
  a: '**Standard** (accès fréquent), **Intelligent-Tiering** (déplace seul selon l''usage), **Standard-IA** et **One Zone-IA** (accès rare, frais de lecture), **Glacier Instant Retrieval** (archive lue en millisecondes), **Glacier Flexible Retrieval** (minutes à heures), **Glacier Deep Archive** (jusqu''à 12 h, le moins cher).'
- q: Que fait une règle de cycle de vie S3 ?
  a: Elle **déplace** les objets vers une classe moins chère après N jours (Standard → IA à 30 jours → Glacier à 90 jours) et/ou les **supprime** (expiration), y compris les anciennes versions et les envois multipart inachevés.
- q: À quoi sert le versioning ?
  a: 'Chaque modification ou suppression crée une **nouvelle version** au lieu d''écraser. Une suppression pose un **marqueur de suppression** : l''objet peut être restauré. Prérequis de la réplication et d''Object Lock.'
- q: Comment empêcher qu'un bucket soit rendu public par erreur ?
  a: '**Block Public Access** activé au niveau du compte et du bucket (actif par défaut sur les nouveaux buckets), et **Object Ownership** en mode « bucket owner enforced » (ACL désactivées).'
- q: Quelles sont les options de chiffrement côté serveur ?
  a: '**SSE-S3** (clés gérées par S3, défaut), **SSE-KMS** (clé KMS : contrôle d''accès à la clé et traçabilité dans CloudTrail), **DSSE-KMS** (double chiffrement) et **SSE-C** (tu fournis la clé à chaque requête).'
- q: Qu'est-ce qu'une URL présignée ?
  a: Une URL qui donne un accès **temporaire** à un objet précis (lecture ou envoi), signée avec les droits de celui qui la crée. Permet à un navigateur d'envoyer un fichier directement dans S3 sans passer par ton serveur.
- q: Différence entre CRR et SRR ?
  a: La réplication **entre régions** (CRR) copie les objets dans une autre région (reprise après sinistre, latence). La réplication **dans la même région** (SRR) copie vers un autre bucket (agrégation de logs, compte séparé). Les deux exigent le versioning.

**S3** (Simple Storage Service) stocke des **objets** : des fichiers de n'importe quelle taille (jusqu'à 5 To), rangés dans des **buckets**. Il sert à tout : sauvegardes, sites statiques, données d'analyse, artefacts de CI, state Terraform. Il offre une durabilité de « onze 9 » (99,999999999 %) : les données sont copiées sur au moins trois AZ, sauf dans les classes One Zone.

> **Les outils cités dans cette fiche.**
> - **objet** : un fichier plus ses métadonnées, identifié par une **clé** (son chemin, par exemple `factures/2026/10/f123.pdf`).
> - **bucket** : le conteneur d'objets ; son nom est **unique dans tout AWS**, ses données vivent dans une région.
> - **classe de stockage** : le niveau de prix et de disponibilité d'un objet (Standard, IA, Glacier…).
> - **KMS** (Key Management Service) : le service de clés de chiffrement d'AWS (fiche Sécurité et chiffrement).
> - **Object Lock** : un verrou qui empêche de modifier ou supprimer un objet pendant une durée (stockage « WORM », écrit une fois, lu plusieurs).
> - **CloudFront** : le réseau de diffusion (CDN) d'AWS, souvent placé devant S3.
> - **artefact** : un fichier produit par une étape du pipeline (binaire, image, rapport) et transmis aux suivantes.
> - **CI** : l'intégration continue : chaque modification de code est automatiquement construite et testée.
> - **state** : le fichier où Terraform garde la correspondance entre le code et les ressources réelles.
> - **AZ** : une zone de disponibilité : un ou plusieurs datacenters indépendants dans une région.
> - **stockage objet** : un stockage de fichiers accessibles par HTTP (S3, Swift, Ceph RGW), peu cher et presque illimité.
> - **EBS** : les disques réseau attachés aux instances EC2.
> - **EFS** : le système de fichiers partagé (NFS) d'AWS.
> - **API** : interface qui permet à un programme d'en piloter un autre par des requêtes (souvent HTTP).

## Comprendre : un stockage objet, pas un disque

| | S3 (objet) | EBS (bloc) | EFS (fichiers) |
| --- | --- | --- | --- |
| accès | API HTTP (`GET`, `PUT`) | monté par **une** instance | monté par **des centaines** d'instances (NFS) |
| modifier une partie | non, on réécrit l'objet | oui | oui |
| taille | illimitée | jusqu'à 64 To par volume | élastique |
| prix au Go | le plus bas | moyen | le plus élevé |

Les « dossiers » de S3 n'existent pas vraiment : `factures/2026/` n'est qu'un préfixe dans la clé. S3 est **fortement cohérent** : un objet écrit est aussitôt lisible.

## Les classes de stockage

| Classe | Accès | Durée minimale facturée | Lecture |
| --- | --- | --- | --- |
| Standard | fréquent | — | gratuite (hors transfert) |
| Intelligent-Tiering | inconnu ou variable | — | gratuite, petit coût de suivi par objet |
| Standard-IA | rare, mais immédiat | 30 jours | payante au Go |
| One Zone-IA | rare, recréable (une seule AZ) | 30 jours | payante |
| Glacier Instant Retrieval | archive lue en millisecondes, une fois par trimestre | 90 jours | payante |
| Glacier Flexible Retrieval | archive, restauration en minutes à heures | 90 jours | restauration payante |
| Glacier Deep Archive | archive légale, restauration en 12 à 48 h | 180 jours | la plus lente |

## Le cycle de vie

```json
{
  "Rules": [{
    "ID": "logs",
    "Filter": { "Prefix": "logs/" },
    "Status": "Enabled",
    "Transitions": [
      { "Days": 30, "StorageClass": "STANDARD_IA" },
      { "Days": 90, "StorageClass": "GLACIER" }
    ],
    "Expiration": { "Days": 365 },
    "NoncurrentVersionExpiration": { "NoncurrentDays": 30 },
    "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 7 }
  }]
}
```

Les deux dernières lignes évitent deux sources de coûts invisibles : les anciennes versions qui s'accumulent et les envois interrompus.

## Protéger les données

- **Versioning** : on ne perd plus rien par écrasement ou suppression ; on restaure une version précédente.
- **MFA Delete** : exige la MFA du root pour supprimer définitivement une version.
- **Object Lock** : rétention en mode **governance** (dérogation possible avec un droit spécial) ou **compliance** (aucune dérogation, même root) ; **legal hold** sans date de fin.
- **Réplication** CRR ou SRR, éventuellement vers un **autre compte** (protège même si le compte source est compromis).

## Qui a accès

1. **Block Public Access** au niveau du compte : la protection anti-fuite principale.
2. **Politiques de bucket** (politique de ressource) : accès entre comptes, obligation de TLS, restriction à un VPC endpoint.
3. Politiques IAM pour les identités du compte.
4. **ACL** : ancien mécanisme, désactivé par défaut (« bucket owner enforced »).
5. **URL présignées** pour un accès temporaire à un objet.
6. **Access Points** : un point d'accès par application, chacun avec sa politique, pour les gros buckets partagés.

```json
{
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": ["arn:aws:s3:::shop-factures", "arn:aws:s3:::shop-factures/*"],
  "Condition": { "Bool": { "aws:SecureTransport": "false" } }
}
```

## Chiffrement

Tout nouvel objet est chiffré par défaut en **SSE-S3**. On choisit **SSE-KMS** pour contrôler qui peut utiliser la clé et tracer chaque usage ; activer les **S3 Bucket Keys** réduit alors fortement le nombre d'appels (et le coût) KMS.

## Performance

- Plus de 100 Mo : **envoi multipart** (en parallèle, reprise possible).
- **Transfer Acceleration** : envoi via les points de présence de CloudFront pour des clients lointains.
- **Byte-range fetches** : lire une partie d'un gros objet.
- S3 tient au moins 3 500 écritures et 5 500 lectures par seconde **par préfixe** : répartir sur plusieurs préfixes augmente le débit.
- Les **notifications d'événements** (vers Lambda, SQS, SNS ou EventBridge) déclenchent un traitement à chaque nouvel objet.

> **À retenir.** S3 stocke des objets, durables sur trois AZ, dans des buckets au nom unique. Choisir la classe selon la fréquence d'accès et automatiser avec le cycle de vie. Versioning, Object Lock et réplication protègent les données ; Block Public Access et les politiques de bucket contrôlent l'accès. SSE-S3 par défaut, SSE-KMS pour contrôler et tracer.
